note bottom of PerfilCliente
Los datos históricos cifrados no implican consentimiento.
FASE 9A: consentimientos independientes (perfil / compras); solo TRUE autoriza.
Hacia la IA solo viaja objetivoNutricional (nunca condiciones médicas ni alergias).
FASE 9C: el historial de compras ENTREGADAS solo ajusta la relevancia en el backend
(ResumenHistorialIA, con autoriza_historial_ia = TRUE); ContextoIA.historialConsumo NO se
envía a Ollama. historialConversacion: no implementado.
FASE 9B-1: EvaluadorAlimentario usa SOLO las restricciones declaradas en la consulta
actual (no las alergias del perfil: FASE 9B-2) y nunca las envía a Ollama.
Las nuevas declaraciones usan PreferenciaCliente.
end note
note bottom of Producto
Inactivo si falta información comercial.
No inventar precio ni existencias.
end note
note bottom of MovimientoInventario
AJUSTE establece conteo absoluto >= 0; motivo obligatorio.
Inicial: anterior NULL; posteriores conservan anterior/nueva.
ENTRADA/SALIDA: cantidad positiva; resultado no negativo.
Producto activo completo: configurar y mover.
Inactivo con inventario: únicamente AJUSTE.
end note
